# E53 답 완료 대기 수리(t-1638)

## 확인한 문제와 한계

E130 후보의 착지 전체 검증에서 E53 직접 답·그림 단계가 `coordinator inbox 원문: undefined`로 실패했다.
수정 없는 main과 로컬 병합 결과에서 각각 12회 비교한 결과 같은 오류는 재현되지 않았다.
별개인 질문 근거 경고 출력 시한 실패가 병합 결과에서 한 번 있었다. 이를 inbox 오류와 같은 실패로 세지 않는다.

보존된 원래 실패의 최종 DB에는 답 알림과 올바른 그림 경로가 있었다. Follow-ups 파일 mtime보다 inbox 생성 시각이
14ms 뒤였으며, 코드도 `thread_message`의 Follow-ups 기록 후 답 알림을 만들고 API 응답을 반환한다.
기존 E53은 pane 출력·Follow-ups만 기다리고 inbox를 즉시 읽어서 이 완료 경계를 보장하지 못했다.
원래 CLI 조회 시각과 API 완료 시각은 없어 최초 실패의 직접 원인으로 확정하지 않는다.

## 승인한 수리 범위

사용자 1A에 따라 E53 시험의 답 완료 대기만 고쳤다.

- 단축키 입력 전에 `/api/v1/call`의 `thread_answer` 응답 관측을 건다. 해당 thread ID도 대조한다.
- 키 입력과 응답 대기를 함께 시작하고 응답 JSON을 끝까지 읽는다. API 오류는 본문을 포함해 실패한다.
- 그 뒤 기존 pane 출력·그림 사본 바이트·답 원문·Follow-ups·inbox 원문·답한 카드 검사를 그대로 수행한다.

제품 코드·알림 처리 순서·기대값·시한은 바꾸지 않았다. sleep·실패 재시도·시험 삭제를 추가하지 않았다.
새 유닛 시험이나 fixture를 늘리지 않고 기존 실제 host·agent E53이 API 완료와 알림 원문 경계를 확인한다.

## 개발 검증

| 검사 | 결과 |
| --- | --- |
| 웹 타입·번들·웹 유닛 전체 | 통과, 유닛 717개 |
| E53 전체 | 통과, 문제의 직접 답·그림 단계 1369ms |
| 직접 답·그림 단계만 새 실험실 10회, worker 6 | 10/10 통과, 단계 1409~1710ms |
| 공개 검사·Git 공백 검사 | 통과 |

관련 owner는 `aaa verify -- nice -n 15 python3 scripts/verify.py develop --base b060fa39d31d62bf2c743deef683989984547b1b --spec 53`으로 확인했다.
반복은 같은 CLI의 고정 사본으로 `web.e2e.mjs --spec 53 --grep '^직접 답 여러 줄' --repeat 10 --workers 6`을 실행했다.
반복에서 E53의 다른 단계를 검사했다고 쓰지 않는다. 기존 전체 gate 실패와 별개 출력 시한 실패 이력도 지우지 않는다.
미커밋 개발 검사라 workspace finish 원장 수집은 생략됐고 결과 로그는 작업 전용 폴더에 보존했다.

이 결과는 최초 inbox 오류의 원인이 확정됐거나 CI가 회복됐다는 증거가 아니다.
착지 gate·병합·push·배포는 이번 수리 범위에 없다.
