# 망 복귀와 잠자기 뒤 웹 재연결

상태 목록과 터미널 출력은 서로 다른 WebSocket을 쓴다. 이전 웹에서 상태 연결이 이미 닫혀 있으면 망 복귀 때 보내는 ping이 아무 일도 하지 않아 예약된 재시도를 기다렸다. 터미널은 재시도 예약과 출력 정지 여부만 살펴, 오래 숨겼다가 돌아와도 브라우저가 열린 것으로 간주한 소켓을 계속 사용했다.

웹은 망 복귀·페이지 재표시 때 대기 중인 재시도를 깨운다. 상태 연결을 다시 열기 전에 기존 기기 확인을 수행한다. 끊긴 망에서 진행 중이던 확인은 새 망에서 다시 시작한다. 10초 이상 가려졌거나 망 단절을 관측하면 상태·터미널의 옛 연결을 정리하고 다시 연다. 터미널은 답을 받지 못한 입력을 미확인으로 끝내고 새 snapshot을 표시한다. 짧은 탭 전환에서는 열려 있는 터미널을 유지한다.

## 실험실

격리한 실제 host·agent에 Chromium과 WebKit을 연결했다. 연결 요청이 연속으로 실패하도록 한 뒤 브라우저 시계를 재시도 예약 시각까지 차례로 진행했다. 다시 성공할 수 있게 한 시점에 online 사건을 보냈다.

| 관측 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 망 복귀에서 상태 연결 요청까지 | 두 브라우저 모두 가상 시각 10초 경과 뒤 요청 | 두 브라우저 모두 가상 시각 진행 없이 요청 |
| 망 복귀에서 첫 상태 목록 수신까지 | 재시도 타이머 뒤에 수신 | 실제 경과 각 16ms, 브라우저당 한 표본 |
| 오래 가려진 동안 기존 터미널의 수신만 차단하고 복귀 | 상태 목록이 돌아와도 새 터미널 연결과 새 출력이 없었음 | 각 브라우저에서 새 연결의 snapshot으로 그동안 발생한 PTY 출력 표시 |

E2E 13은 브라우저 시계를 정지한 채 복귀 사건이 상태 연결을 깨우는지 본다. 숨긴 동안 실제 셸에 출력한 표지가 이전 터미널에 없고 복귀 뒤 새 snapshot으로 보이는지 확인한다. 연이어 온 pageshow와 짧은 탭 전환이 추가 터미널을 열지 않는지도 검사한다. E2E 07·23·97·109가 출력 정지, 떠나는 문서, 압축과 첫 화면, 보관 중인 작업 복귀를 각각 검사한다.

개발 검증에서 웹 타입·번들, 단위 시험 718개, E2E 01·02·05·07·13·23·97·109, 공개 검사를 통과했다. 웹 클라이언트만 변경했다. 표의 시간은 loopback 측정값이며 실제 운영망의 응답 시간은 기기에서 따로 잰다.
