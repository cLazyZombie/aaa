# 배포 후보 전송의 무응답 한도 (t-2149)

두 배포 모두 원격 대상이 256KiB 조각을 150개와 151개까지 확인한 뒤 멈췄다.
host가 다음 저장 요청에 준 시간은 각각 726ms와 106ms였다. 전송 중 매번 단계 시작 시각에서
120초를 세어, 새 조각의 수신이 확인돼도 다음 요청에 줄 시간이 줄었다. 마지막 요청 시한이 끝나자
재개 대기에서도 같은 기한이 만료돼 rollout을 중단했다. EOF를 검사할 조각까지 가지 못했다.

## 회귀 조건

`rollout::transfer_tests`는 임시 host DB와 Agent link 요청·영수증으로 진행기를 실행한다.
DB의 시각을 미리 정하고 요청에 답하며 진행하므로 시험 중에 120초를 기다리지 않는다.

- 180초 전에 시작해 90초 전에 마지막 바이트를 확인한 전송을 재개한다. 같은 offset 조회 뒤에는
  남은 30초 안에 다음 조각을 보내야 하고, 그 조각의 영수증 뒤에는 다음 쓰기에 새 기한이 주어져야 한다.
- 대상이 조각을 저장한 뒤 응답을 잃으면, 같은 rollout ID로 조회해 대상에만 남은 새 offset을 DB에
  보존한다. 마지막 조각의 완료 영수증을 받아 다음 사전 검사에 도달하는지와 원래 시작 시각을 확인한다.
- 확인한 바이트가 없으면 시작 시각부터, 바이트가 있으면 마지막 진척부터 120초에 멈춘다.
  중단 원인에는 머신과 마지막 확인 바이트 수가 남는다. 사전 검사에는 단계 시작 기준을 적용한다.

수정 전에는 첫 시험이 이미 확인한 바이트 하나만 남기고 후보를 정리해 실패했다.
수정 뒤 두 시험이 통과했다. 실제 수신 파일의 이어 쓰기와 EOF SHA 검사는
`aaa-agent`의 `transfer_resumes_durable_offsets_and_checks_sha_before_execution`이,
바이너리의 링크 왕복은 [기존 t-0525 시험](testing.md#배포-후보의-바이트-보존t-0525)이 검증한다.
