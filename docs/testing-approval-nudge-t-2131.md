# 승인 알림과 host 공용 잠금 검증

승인 답을 기록한 뒤 coordinator가 쉬고 있어도 기존 ticker는 보고서 정리와 프로젝트 점검을 모두 마쳐야 입력창을 검사했다. 실험실의 host와 메모리 전송으로 연결한 agent에서 승인 항목을 만들고, 실제 Screen·Input 요청과 Enter 수신을 관측했다.

| 독립시킨 작업 | 회귀 시험이 확인하는 순서 |
| --- | --- |
| ticker의 보고서 정리 | 보고서 잠금을 잡고 일반 tick을 시작한다. 잠금을 풀기 전에 coordinator가 승인 알림을 받는다. |
| pane 목록의 로컬 경로 정규화 | 실제 목록 조회의 경로 판정을 멈춘다. 그동안 다른 pane의 조회·붙기와 coordinator의 알림 수신이 끝난다. |
| 공개 주소 판정 | 파일 DB의 쓰기 트랜잭션을 연 채 공개 주소를 읽으면 이전 확정 주소가 보인다. 커밋 직후에는 새 주소, 매핑을 해제한 뒤에는 빈 값이 보인다. |
| hook과 pane 전달 경합 | 붙여넣기를 받는 순간 hook이 요청해도 같은 항목은 한 번 전달한다. 이후 새 승인 묶음에도 이미 보낸 항목을 섞지 않는다. |
| 사용자 입력 | 두 번 빈 창을 관측한 뒤 생긴 초안에는 붙여넣기가 없다. 붙여넣기 뒤 사용자 키가 오면 Enter를 보내지 않고 그 글을 보존한다. |

실제 대기 설정을 따르는 시험에서는 idle·quiet 창을 유지한다. 브라우저 E2E 117은 별도 pane의 알림 수신 중 웹 초안, 커서, 한글 조합과 메시지 본문을 검사한다. Rust owner는 `aaa-host`의 `inbox::hook_tests`와 `web_publication::tests`다.

## 전후 표본

종료 thread 2,122건과 처리된 inbox 21,315건을 합성했다. 일반 ticker를 깨우고 같은 로컬 pane을 1,500회 조회했다. 실험에 한해 idle·quiet 설정을 0으로 두고 두 번의 빈 창 관측과 제출 직전 검사는 유지했다.

| 관측 | 기준판 | 수정판 |
| --- | ---: | ---: |
| 승인 기록 시작 → inbox 발행 완료 | 12.03ms | 12.33ms |
| 승인 기록 시작 → agent의 Enter 수신 | 1,822.11ms | 546.84ms |

공개 주소를 연속 조회한 별도 실험에서는 옛 임무 알림 점검이 DB 연결을 점유한 126.316ms와 주소 조회의 126.371ms 대기가 같은 밀리초에 끝났다. 점검 범위를 줄이고 별도 읽기 연결로 확정 주소를 조회한 뒤 같은 실험의 최장 조회는 3.406ms였다. 이 수치는 각 조건에서 한 실행의 관측값이다. 판정은 위 사건 순서로 한다.
