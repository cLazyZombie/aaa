# 열린 질문 카드의 선택 안내와 별개 승인

11월 24일 q-4834의 열린 카드 뒤에 “보시고 하나를 골라 주세요”를 붙이자 카드 누락 경고가 떴다. 이어 q-4843과 q-4844를 번호 목록으로 소개하고 “두 질문 모두”에 고르는 법을 안내한 턴에도 같은 경고가 떴다. 13:04의 로컬 시안 브랜치 삭제 승인은 실제로 카드가 빠져 있었고, 뒤이어 q-4831이 올라왔다. 시험에는 판정에 필요한 구절과 관계를 남기고 나머지 글과 링크를 재구성했다.

## 판정 경계

- 링크의 제목과 주소를 건너뛰고 문장 안에서 각각의 요청 위치를 잡는다. 같은 문장에 별개 요청이 붙어도 앞 요청이 쓰는 카드 번호를 넘겨주지 않는다.
- 제목과 목록 항목은 CommonMark의 소스 위치를 따른다. 앞에 소개한 카드 하나를 가리키는 선택 안내는 같은 주제의 설명과 빈 줄을 건너 연결한다. 보충 정보 요청에는 들여쓴 같은 목록 항목의 열린 카드 하나가 필요하다.
- 질문 수를 밝힌 공통 선택 안내에서는 같은 주제의 번호 목록을 사용한다. 각 항목을 여는 카드 링크가 하나씩 있어야 하며 서로 다른 카드의 수가 안내에 적힌 수와 같아야 한다. 항목 설명에 언급한 다른 번호는 그 수에 넣지 않는다.
- 연결 뒤에 현재 프로젝트의 카드 상태를 확인한다. 일반 선택 안내가 가리킨 번호가 이미 답했거나 닫혔으면 오래된 카드 경고를 낸다. 대상이 모호하거나 모르는 번호면 누락 경고를 낸다. 같은 턴에 실제 접수한 카드가 있어도 뒤에 붙인 별개 질문이나 승인은 감시한다.

단위 시험은 열린 카드가 실제로 연결됐는지와 경고 종류·행·연결 번호를 확인한다. Host 시험은 실제 질문 접수, 완료 사건, inbox 조회, 같은 사건 재수신, 카드 닫기, 다음 완료 사건의 순서로 실행한다. 브랜치 삭제 승인은 inbox 경고 한 건으로 남고 재수신으로 늘지 않는다. 카드를 닫은 뒤 같은 안내는 닫힌 번호를 포함한 오래된 카드 경고가 된다.
