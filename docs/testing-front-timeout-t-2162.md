# 로컬 CLI 시간 초과와 caller 조회 검증

- 가상 시계와 실제 frame 송수신으로 Welcome이 오지 않는 경우를 확인한다. 10초에 첫 응답 시간 초과와 요청 미전송이 표시되고 요청 frame이 없다.
- host의 timeout 응답은 기존 오류 코드를 보존하고 요청 처리 단계와 경과를 표시한다. 같은 timeout을 조회와 변경에 돌려주고 변경만 결과 미확정인지 확인한다. 변경을 받은 뒤 reply 연결이 끊겨도 결과 미확정이다.
- 실제 CLI 프로세스의 `post`를 임시 소켓에 붙여 첫 응답이 끊기면 그 실패가 보이고, Welcome 뒤 timeout 응답에는 결과 미확정이 보이는지 확인한다.
- pane 인덱스가 없던 DB에 오래된 thread 기록과 깨진 JSON을 두고 인덱스 생성과 조회를 확인한다. 이어 정상 기록으로 host를 다시 연다. 같은 pane의 끝난 기록을 건너뛰고 기존 순서에서 처음 만나는 열린 기록을 쓰며, 연결한 CLI의 보기 권한 제한이 유지된다.

## 격리 실험

운영에서 확인한 기록 수와 크기를 바탕으로 합성 thread 2,162건(약 8.6MB)을 만들었다.
양쪽 모두 같은 verify profile에서 실제 host Front 처리 함수에 연결해, thread에 속하지 않은 pane을 알린 Hello부터 Welcome을 읽을 때까지 16번 쟀다.

| 코드 | 중앙값 | 범위 |
| --- | ---: | ---: |
| thread 전문 전수 조회 | 54.82ms | 52.33~64.25ms |
| pane 인덱스 조회 | 0.11ms | 0.10~3.89ms |

측정은 프로세스 내부 양방향 스트림에서 수행했다. OS 소켓 연결·접근 확인과 운영 부하는 이 표본에 포함되지 않는다.
운영에서 발생한 10초 지연은 이 실험으로 원인이 확정되지 않았다. host는 첫 응답까지 각 단계가 500ms 이상이면 단계·경과·peer PID를,
일반 요청 처리가 5초 이상이면 그 경과를 기록한다. 첫 응답 단계의 마지막 시점은 writer 대기열 등록이다.
