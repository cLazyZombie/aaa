# 계정 요금제 선택과 5시간 창 검증

2026-11-03, t-1484. [제품 정책·공식 근거](account-plans.md).

## 확인한 계약

- 직접 선택한 요금제는 host 재개방·재로그인 뒤에도 유지한다. 자동 감지 원본은 별도로 보존한다.
- 다른 제공자의 요금제·모르는 ID는 거부하고, 보기 전용 기기·세션 안 agent는 변경할 수 없다.
- 선택은 인증 파일·인증 세대·작업 실행을 바꾸지 않는다. 읽기 전용 기기에는 등록 계정의 요금제 이름을 숨긴다.
- 제한 없는 5시간 창은 표시·배정에서 제외하고 주간 관측은 유지한다.
- 정상 응답의 null·누락은 제공 안 됨이다. 과거 숫자·관측 시각은 접힌 기록으로만 남긴다.
- 마지막 정상 관측도 현재 입력 상태를 따른다. 리셋이 지난 5시간 값을 배정 잔량으로 되살리지 않는다.

전체 착지 gate·양 OS cross·Windows production은 착지 창의 최종 통합 SHA에서 수행한다.

## 실패에서 확인한 원인과 수정

- 처음 컴파일에서 기간 상수를 정수로 추가해 기존 부동소수 단위와 맞지 않았다. 단위를 맞춰 컴파일·strict Clippy를 통과했다.
- 창 존재 선언과 숫자의 유효성을 섞어 기존 입력 상태 합치기 시험이 실패했다. 상태줄의 존재 선언은 유지하며,
  OAuth의 null은 재조회 시각보다 실제 새 창 관측으로만 대체하도록 고쳤다. 기존 기대값은 유지했다.
- E2E의 상대 `has` 안에 바깥 region 선택자를 다시 넣어 요소를 찾지 못했다. 계정 ID·안쪽 창의 상대 선택자로 고쳤다.
- 닫힌 select의 option 표시를 기다리던 시험은 select 표시·선택 상태를 기다리도록 고쳤다.
- 휴대폰의 새로고침은 계정 상세를 복원해 목록 탭이 없다. 복원된 상세에서 저장값을 검사한다.
- 응답 수신 직후 화면 반영 전의 선택값을 검사하던 경계는 서버 응답과 DOM의 선택 완료를 함께 기다린다.
  제품도 목록 재조회를 마친 뒤 요금제 선택의 바쁜 상태를 해제한다.

실패를 재시도·시한 연장·기대값 완화로 통과시키지 않았다.

## 새 시험이 필요한 이유

- 계정 meta 시험: 사람 권한·제공자 경계·선택 보존을 실제 host DB와 인증 금고로 확인한다.
- 배정 시험: 해당 없음·현재 제공 안 됨·지난 5시간 기록이 고갈·문턱·순위 판단에 들어가는 회귀를 막는다.
- quota 병합 시험: 재조회한 오래된 상태줄이 OAuth null을 새 관측으로 덮는 회귀를 막는다.
- Codex 변환 시험: 등록 계정의 선택 정책과 모델별 주간 창을 하단 표시가 잃지 않게 한다.
- E2E 125: 실제 웹 드롭다운 → host 저장 → 새로고침·자동 감지 복귀와 읽기 전용 경계를 지킨다.
- E2E 124 수정: 새 표시 계약에 맞춰 기본 접힘·과거 숫자·제공 안 됨을 함께 확인한다.
