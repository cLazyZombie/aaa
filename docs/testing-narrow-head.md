# 좁은 머리줄의 보조 단추를 「⋯」로(t-1987)

## 문제
320px 휴대폰의 thread pane 머리줄은 단추(목록·자동 병합·상태·보고·요약·찾기·대화 전환·⋯)가 제목 칸을 0px로 만들고 「⋯」를
화면 밖으로 밀었다. 목록이 옆에 붙은 769px 창(머리줄 400px, 단추 글자가 보이는 폭)도 같았다. 390px는 제목 칸이 40px였다.

## 수리
머리줄 폭이 520px 이하면(`Term.tsx` `TIGHT_HEAD`, ResizeObserver) `data-tight`를 달고 보고·작업 요약·자동 병합 단추와 단추 글자를
숨긴다. 같은 일은 「⋯」 메뉴 맨 위 항목(`open-report-item`·`summary-item`·`auto-merge-item`)이 한다. 요약·자동 병합 항목은 숨긴
단추에 요청 번호로 시켜, 요약 popover 자리(「⋯」 아래)·자동 병합 저장 실패 띠·값 되돌림을 그대로 쓴다.

실측(fake Claude, 진행률 50%, 대화 보기, 제목 칸 px 전→후): 320 0→94, 390 40→164, 769 0→194, 900(머리 531px) 98→98.
「⋯」가 밖으로 나가는 폭은 없어졌다.

## 자동 시험
- E2E127: 320px Chromium·390px WebKit은 좁은 머리(단추 셋 숨김, 메뉴 맨 위 「보고·작업 요약·자동 병합」, 넘침 없음, 제목 80px 이상)와
  메뉴로 연 요약 시트의 계정을, 목록이 붙은 769px(좁음)·1000px(넓음, 단추 그대로) Chromium은 머리줄을 본다. 1280px는 넓은 머리.
- E2E12: 390px에서 메뉴로 자동 병합을 켜고(✓, `thread show` 값) 1280px 스위치로 끄며, 390px 메뉴 「보고」로 보고 화면에 간다.
- 숨김 규칙(`style.css` `[data-tight]`)을 빼면 E2E127 「목록이 붙은 Chromium 창의 머리 줄」(769px, 제목 22px·단추 셋 보임)과
  E2E12 「휴대폰 머리줄 자동 병합」(390px, 스위치가 보임)이 실패하는 것을 확인했다.
- 일회성 측정: 진행률이 없는 thread(상태 칩 「입력 대기」)도 320px에서 「⋯」 오른쪽 끝 312px, 제목 77px(대화 보기)~117px였다.
