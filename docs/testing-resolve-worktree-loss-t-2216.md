t-2212는 착지 뒤 원본 폴더가 먼저 없어졌다. 자료가 이미 r-17033에 보존됐어도 종료가 막혔고, 복사를 생략하자 d-1326이 확인 대상으로 남았다. 기준 코드에는 작업 폴더의 부재를 그대로 허용하는 경로도 있었다. 보관 여부를 판정하지 않으면 이 경로가 미회수 첨부를 놓친다.

Git 실험에서 worktree 등록과 `.aaa`는 남기고 checkout의 `.git`을 없애자, 일반 `git worktree remove`는 작업 폴더 검증에서 실패했다. 또한 종료 중 branch를 먼저 지우면 그 이름으로 원격 main 포함을 다시 확인할 수 없다.

## 확인 범위

- 원본 폴더 부재를 확인하면 호스트가 받은 최신 본문 해시와 r-ID 판을 대조한다. 첨부 목록과 크기, 실제 바이트의 해시를 함께 본다. 이미 알게 된 더 새 보고와 부분 사본은 종료를 보류한다. 자동화 기억은 이 보고 판만으로 마지막 회수를 검증할 수 없어 원본 회수가 필요하다.
- Git 준비 응답을 잃으면 준비 기록에서 경로를 찾는다. 실행 요청을 보낸 적이 없고 세션·보고 회수 기록도 없는 실패는 `.aaa`가 생성되기 전에 끊겼을 수 있으므로 Git 자리를 정리한다.
- `.aaa` 기록만 남으면 agent의 준비 기록에서 자리·저장소·branch 소유권을 확인하고 그 thread의 폴더를 정리한다. Git 등록과 branch는 이전 경로대로 정리한다. 다른 파일·등록·잠금은 그 자리의 정리 근거를 따로 확인한다.
- 원격 main 포함 근거는 branch 삭제 전에 보존한다. 삭제 응답을 잃으면 요청 당시 branch 끝이 여전히 원격 main에 포함됐는지 다시 확인한다. 종료가 확정되면 기존 조건으로 연결된 할 일을 보관한다.
- 본문·첨부를 모두 작성한 뒤 마지막 보고를 쓰고, 복사와 작업 자리 정리는 resolve에 맡긴다. 원본이 이미 삭제됐고 호스트가 그 뒤의 변경을 관측한 적도 없다면 그 변경은 확인할 수 없다.

## 회귀 시험

- Host 단위 시험에서 정상 사본, 보관 본문 손상, 첨부 목록 누락, 같은 크기의 첨부 손상, 부분 사본, 이미 관측한 새 보고를 대조한다.
- 실제 CLI·host·agent·Git으로 작업 폴더 전체 삭제, 기록만 남은 폴더, 미회수 첨부를 검사한다. 로컬 연결과 별도 상태 폴더를 가진 TLS 원격 agent에 같은 시나리오를 적용한다.
- Git이 branch를 지운 뒤 정리 응답을 기다리는 사이에 호스트를 다시 띄운다. 재개된 종료가 정리 Next를 처리하고 종료 사건을 한 번 기록하는지 확인한다.
- 정상 종료 뒤 보고와 첨부 바이트, Git 자리 및 branch 정리, 할 일 자동 보관, 사본 실패·할 일 확인 알림 부재를 확인한다. 미회수 작업은 종료가 차단되고 복사를 명시적으로 생략하면 연결된 할 일이 확인 대상으로 남는다.

## 참고

Git은 정리할 worktree 하나를 지정한다. 디스크가 빠진 다른 자리도 지울 수 있는 저장소 단위 prune은 사용하지 않는다. 외부 코드는 가져오지 않았다. [Git worktree](https://git-scm.com/docs/git-worktree), [GPL-2.0](https://github.com/git/git/blob/master/COPYING)

restic의 데이터 검증은 목록을 검사한 뒤 보존 바이트를 다시 읽는다. 보고 사본도 목록과 보존 파일의 내용을 함께 검증한다. [restic check](https://github.com/restic/restic/blob/master/doc/man/restic-check.1), [BSD-2-Clause](https://github.com/restic/restic/blob/master/LICENSE)
