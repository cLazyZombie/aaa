# 터미널 WebSocket의 업그레이드와 첫 상태(t-2128)

터미널 WebSocket은 기기와 Origin을 확인하고 host의 pane 상태 표에서 ID를 찾은 뒤 업그레이드한다. 프로젝트와 계정 조회는 이 경로에서 하지 않는다. 없어진 pane에는 HTTP 404를 보낸다.

`state=grid.v1`을 보낸 웹의 첫 상태와 상태 변경에는 터미널 크기와 조작권만 싣는다. 연결 여부·실행 상태·기기 권한·색상 준비로 결정한 읽기 전용 판정은 기존 메시지로 먼저 보낸다. 구 웹에는 기존 `state`를 보내고, 새 웹은 구 host가 보낸 `state`도 받는다. 크기 변경은 앞서 받은 snapshot과 출력을 적용한 뒤에 처리한다. 프로젝트·계정이 들어가는 일반 pane 목록과 CLI의 조회는 여기와 별개다.

- host 단위 시험은 SQLite 연결을 쥔 상태로 터미널 크기·조작권 메시지를 읽는다. 결과를 받은 뒤에 잠금을 풀며, 시한은 교착 검출에 쓴다.
- E2E02에서 변경된 크기 메시지를 잠시 붙잡아, 앞서 받은 화면의 크기와 입력 위치를 재는 계약을 확인한다.
- E2E97은 Chromium과 WebKit에서 WebSocket을 직접 열어 host와 브라우저가 같은 붙기 ID를 남기는지 확인한다. agent가 색 응답을 보내기 전에 첫 화면을 표시하고 그 뒤에 입력을 허용하는 순서도 확인한다. 기본 주소에서는 붙기 ID를 보내지 않는다.
- `?trace=attach`를 선택한 조작 기기는 Console의 `ws-request`·`ws-open`과 host의 「웹 터미널 요청」·「웹 터미널 upgrade」를 `attachId`/`attach_id`로 맞춘다. host의 `before_handler_us`에는 `origin_us`가 포함된다. 인증, pane 상태 잠금 대기·보유, 101 응답을 만들기 직전의 host 시각을 따로 남긴다. 브라우저와 host의 절대 시각을 비교할 때는 두 시계의 차이를 고려한다. 생성한 ID에는 기기 정보나 주소가 없고 이 계측은 세션 내용·인증 값을 남기지 않는다.

공용 host 상태 잠금을 기다리는 시간은 여전히 측정한다. 다른 경로가 이 잠금을 잡고 느린 작업을 하면 터미널도 영향을 받는다.
