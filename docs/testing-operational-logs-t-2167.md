# 카드 답과 웹 연결 운영 로그 검증

카드 답을 받는 API, 알림함 투영, coordinator 알림 전달의 시간과 결과를 남긴다. 알림은 같은 묶음과 pane에서 이미 남긴 보류 이유를 반복하지 않는다. 활동 상태, 화면 판정, 입력창 안정 대기, 실제 붙여넣기·Enter·수락 각각을 확인할 수 있다. 웹 상태 연결은 초기 상태 송신까지, 대화창 연결은 화면 사본 적용 ACK까지 잰다. ACK를 지원하지 않는 화면은 사본을 전송 대기열에 넣기까지 잰다.

## 확인 경로

- Rust 알림 시험은 보류 이유가 번갈아 나와도 한 번만 남기며, 새 묶음이나 다른 pane의 이유는 새로 남기는 경계를 확인한다.
- Rust 웹 시험은 다른 기기의 계측, 최대 시간을 넘긴 값, 허용 필드 밖 본문을 거부하고 같은 응답의 계측을 한 번만 받는다. 발급 번호의 256개 상한과 2분 만료도 확인한다.
- E2E 69는 WebKit 휴대폰 화면으로 답을 보내고, 답한 카드로 바뀌며 응답의 추적 번호와 두 단계 시간만 보내는 것을 확인한다. host 로그에서 답 원문 없이 알림함 등록과 실패한 답의 브라우저 계측을 확인한다.
- E2E 53과 97은 기존 답 처리 경합과 터미널 연결·압축 계약을 확인한다.

## host.log 검색

```sh
grep -E 'web_rpc|web_answer|answer_inbox|inbox_nudge|pane_attach|web_events' host.log
grep -F '<trace 값>' host.log
grep -F '<inbox 값>' host.log
```

`web_rpc`와 `web_answer`는 `trace`로, `answer_inbox`와 `inbox_nudge`는 `inbox` 값으로 잇는다. 카드가 만든 알림함 줄은 같은 `card_answer` 추적 번호도 붙는다. 알림 묶음에 카드 답이 여러 개면 `answer_ids`에 최대 다섯 개를 싣고, 묶음의 경과 시간은 가장 오래 기다린 카드 알림을 우선하여 잰다. `input_id`로 기존 `입력 사건` 줄도 함께 찾을 수 있다.

서버 요청은 500ms 이상 또는 실패일 때 남긴다. 브라우저는 응답을 읽기까지 500ms 이상이거나, 응답 뒤 카드 상태 갱신과 화면을 그릴 기회까지 250ms 이상이거나, host 처리가 500ms 이상이거나 실패이면 남긴다. 카드 응답 헤더를 받지 못했거나 탭이 숨겨진 경우에는 브라우저 계측이 없을 수 있다.
