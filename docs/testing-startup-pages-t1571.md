# 웹 첫 화면의 부분 목록과 답변 이력 검증

첫 화면이 과거 작업·완료 답변 전체 다운로드를 기다리는 경로를 분리했다. 검증은 운영 기기를 등록하지 않는 격리 host·agent에서 수행한다.

## 관련 owner

- `aaa-host asks::tests::history_pages_keep_index_links_bounds_and_deleted_cursor`: 큰 원문 바이트 경계, 50개 상한,
  동일 시각의 페이지 순서, 삭제된 커서, 프로젝트 분리, 과거 단건 원문, 구판 전체 응답.
- `aaa-proto`: 생성 TypeScript, Reader 조회 권한, 기존 요청 호환과 버전 협상.
- `web/test/threadReload.test.mjs`: 부분 표시, 페이지 오류, 겹친 재연결, 사건 우선 병합.
- `web/test/asksReload.test.mjs`와 `asksModel.test.mjs`: 첫 읽기와 사건 병합, 답 응답 우선, 실패 뒤 실제 사건으로 복구,
  원문 없는 과거 링크·배지, 삭제·페이지 중복 제거.
- E2E12: 기존 2,500건 전체 페이지·겹친 재연결·실제 Chromium/WebKit DOM 검사를 유지한다.
  열린 항목 우선 조회와 전체 스냅샷 스트림은 구별해서 관측한다.
- E2E129: 실제 host의 작업 1,571건·완료 답변 250건. 전체 목록 요청을 보류한 동안 열린 목록과 끝난 작업 직접 링크를 표시한다.
  과거 선택 복원, 보류·실패·끝난 작업 전체 목록과 거르기, 초기 asks 요청 한 번, 첫 쪽 밖 q-ID 원문,
  완료 개수와 모든 페이지 열람을 Chromium 데스크톱·WebKit 휴대폰에서 확인한다.
- E2E113: 자동 답변이 섞인 대량 이력도 첫 50줄 표시·전체 삭제 대상을 보존한다. 원문 페이지와 목록 줄 수는 분리한다.
- 기존 질문·답변·삭제·자동 결정 E2E와 전체 gate에서 새 질문·답 사건의 실제 왕복도 함께 확인한다.

새 시험은 HTTP 요청·응답, DOM 상태, 실제 drawer 애니메이션 완료로 끝낸다. 고정 sleep·재시도·시한 연장은 추가하지 않는다.
초기 시험의 검색 입력 역할(`searchbox`)과 휴대폰 drawer 여는 경로 오류는 시험 코드를 수정해 해소한다.

## 전후 측정 경계

설치된 기준 실행 파일과 이 worktree의 release 실행 파일을 같은 격리 설정·상태 자료·브라우저에서 비교한다.
작업 1,570건(열린 것 7개), 완료 답변 250건(전체 응답 약 2.1 MB)을 쓰며, 별도의 Reader 기기만 스스로 페어링한다.
첫 방문과 HTTP 캐시 재방문은 새 탭에서, 40 ms 요청 지연·20 Mbit/s 조건을 각각 세 번 잰다.
CDP 전송 제한이 서비스 워커 요청을 빠뜨리므로 제한 조건에서는 SW를 막고 HTTP 캐시는 유지한다.
실제 SW 재실행은 제한 없는 별도 조건으로 관측한다. 브라우저 DOM 뒤 두 frame을 첫 화면 표시 경계로 쓴다.

개인 경로·인증 정보·원문 자료는 공개 저장소에 남기지 않는다. 개별 실행의 수치·로그 위치·결과와 남은 한계는 작업 보고에 둔다.
실제 모바일 PWA 프로세스 복원·WAN RTT·터미널 재생은 이 합성 실험의 측정 범위를 넘는다.
