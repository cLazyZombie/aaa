## 보고 글·diff 줄 의견과 인용 위치로 돌아가기(t-1222, plan §8.531)

- 웹 유닛 `node --test web/test/reviewNotes.test.mjs`(9개)는 순수 규칙을 본다.
  - 인용 꼴: 보고 판 머리와 `>` 줄, diff 기준(`main 대비 <sha8>`·`미커밋`)·파일·줄(새·옛, 쪽이 갈림)과 표지 붙은 `diff` 울타리(글 안 backtick보다 긴
    울타리), `의견:` 줄(빈 의견은 없음). 필요한 이유: agent가 받는 글의 계약이다.
  - 보낸 글 다시 읽기: 네 꼴(보고·diff·터미널·대화)의 머리·원문, 깨진 인용 건너뛰기, 돌아가기 단추 이름. 필요한 이유: 돌아가기는 이 꼴만 읽는다.
  - diff 줄: 실제 `parsePatchFiles` patch의 한 줄 보기 차례·옛/새 번호, 아래에서 위로 고른 범위 바로잡기, 없는 줄, 전체 파일을 읽은 diff의
    hunk 밖 맥락 줄. 필요한 이유: 줄 고르기는 번호·쪽만 주므로 원문을 다시 세워야 한다.
  - 글 자리: 같은 글 둘 중 문맥으로 고른 곳, 앞에 줄이 더해진 뒤 찾기, 문맥 없는 인용은 처음 나온 곳. 필요한 이유: 보고 글 「위치」의 정확성.
  - 의견 모음: 보낼 차례와 이은 글, thread별 저장·깨진 항목 버림·바뀌지 않은 목록의 같은 객체(useSyncExternalStore). 필요한 이유: 모음의 저장 계약.
- 웹 E2E120 `120-review-notes`는 실제 host·agent·PTY의 git 저장소 thread(fake profile, Claude hook으로 대화 보기)에서 세 단계를 본다.
  필요한 이유: 고른 글·shadow DOM 줄 번호·화면 사이 넘김·초안 붙이기는 실제 브라우저와 pane 화면이 있어야 확인된다.
  - Chromium 1280: 보고 글을 고르고 「의견」→ 의견 모음과 칠함, diff 줄 번호를 눌러 「의견」→ 줄 아래 카드, 고른 줄을 푼 뒤 「위치」로 다시
    고름, 「메시지에 넣기」→ pane 대화 입력창 초안이 보고·diff 의견 글과 같고 모음이 비며 PTY로 보내지 않음.
  - Chromium 1280: 보낸 말 속 네 인용의 「돌아가기」(대화는 찾기 칸의 활성 찾음이 답의 그 글, 터미널은 터미널 보기와 고른 줄 띠, 보고는
    thread 화면에서 그 글을 고름, diff는 diff 칸의 그 줄을 고르고 「바뀌었다」 띠 없음), 대화에서 고른 글의 「의견」이 인용 아래 `의견:` 줄로 붙음.
  - WebKit 390: 보고 글 「의견」·「의견 추가」 tap(마우스만 pointerdown을 막는 t-1204 수리 유지).
- 고정 sleep·재시도·시한 확대·기대값 완화는 없다. 완료는 DOM 상태·PTY 출력으로 본다.
