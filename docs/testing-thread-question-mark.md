# 작업창 질문 대기 표지 검증

## 변경 계약

- 작업 목록 thread의 모델 아이콘 오른쪽 아래에 작은 `?`를 붙인다.
- 「답할 것」과 같은 미답변 보고 판정(`asks`)을 쓴다. 일부 답은 질문이 남아 있으므로 표지를 유지한다.
- 실행 중인 pane이 확인창에서 기다릴 때도 표시한다. 실패·정리 문제 등 질문 없는 확인 필요 상태는 표지의 근거가 아니다.
- 머신 독점 자물쇠와 모서리 배치·원형 배경·크기를 공유한다. 질문은 기존 확인 필요 색을 쓴다.
- 접근성 이름에도 「질문 대기」를 더하며 줄을 누르면 여전히 해당 pane을 연다.

## 관련 owner와 새 시험 이유

`web/e2e/specs/121-thread-question-mark.mjs`는 실제 host 보고 수집에서 웹 표지까지, 일부 답과 전체 답,
답한 질문의 재보고를 잇는다. 순수 질문 판정 시험만으로는 사건을 받은 작업 목록의 표시·해제나 아이콘 배치를 확인할 수 없어 필요하다.
Chromium·WebKit의 1280·390 화면과 Claude·Codex 로고, 한 줄·두 줄 모드를 함께 검사한다.
기존 질문 답 전송 owner인 E2E 53과 공유 배치의 머신 독점 owner인 E2E 99도 확인한다.
고정 sleep·재시도·상한 완화는 추가하지 않는다.

## 참고

- 저장소의 `web/src/herdr/Sidebar.css`·`AgentMark.tsx`와 기존 머신 자물쇠를 재사용한다. 기존 로고 라이선스 고지를 유지한다.
- [Lucide](https://lucide.dev/icons)의 question 계열([ISC](https://lucide.dev/license))과
  [Primer 구성요소](https://primer.style/product/components/)를 비교했다.
  이미 작은 원형 배경이 있는 자리라 외곽 원을 더 그리는 아이콘 대신 `?` 글자 하나를 쓴다. 새 의존성·외부 코드는 추가하지 않는다.

## 결과

첫 개발 검사에서 타입·번들·웹 유닛 675개와 E2E 53·99는 통과했다.
E2E 121의 첫 기준 상태 대기는 실패했다. `[진행 중]`이라는 보고 첫 줄만 쓰면 작업 중이 된다고 fixture가 잘못 가정했다.
실제 host는 미확인 새 보고를 검토 대기로 묶는다(`orch.rs`의 `thread_group` 5번 규칙).
시험 세션이 실제 `aaa report --percent 50`을 보내도록 fixture를 고쳤다. 대기 상한·표지 단언은 유지했다.

검증 중 문서를 추가한 첫 실행은 출처가 바뀌어 원장 요약이 수집되지 않았다.
수리 뒤 커밋을 고정하고 관련 검사를 수행한다. 착지 gate는 착지 창의 최종 통합 SHA에서 수행한다.
